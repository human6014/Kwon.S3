# S3 — 구글 스프레드시트 데이터 파이프라인

기획 데이터를 구글 스프레드시트에 적으면, 에디터 툴이 C# 클래스와 ScriptableObject 에셋을 만들고,
에디터가 같은 시트 내용을 AWS 버킷에 올리면, 빌드된 게임은 실행할 때 CloudFront에서 최신 데이터를 받아온다.

```
기획자 → 구글 시트 ──[에디터: 굽기]────> Assets/02.Script/Data/*.cs
                  └─[에디터: 업로드]──> S3 버킷 ──> CloudFront ──> 런타임 갱신
```

시트는 **저작 도구**이고 AWS가 **배포 채널**이다. 굽기와 업로드는 별개 동작이다 —
굽기는 이 프로젝트의 코드·에셋을 갱신하고, 업로드는 이미 배포된 게임이 받아갈 데이터를 갱신한다.

S3는 자체 어셈블리로 분리된 **패키지**다. 산출물(생성 코드)과 설정만 프로젝트 쪽에 남는다.

```
Packages/com.kwonstudio.s3/            ← 패키지 (설치하면 읽기 전용일 수 있다)
├── KwonStudio.S3.asmdef            런타임 · 전 플랫폼 · references: [UniTask]
├── Parsing/  Table/  Remote/
└── Editor/
    └── KwonStudio.S3.Editor.asmdef 에디터 전용 · references: [KwonStudio.S3, UniTask]

Assets/                                ← 프로젝트 (설정과 산출물이 사는 곳)
├── Resources/S3/S3Settings.asset          배포 주소 · 문서 ID — 런타임이 읽는다
├── Settings/S3/S3ImportSettings.asset     시트 탭 목록 · 생성 경로
└── 02.Script/Data/                        생성된 스크립트 — 직접 수정하지 말 것
```

- 에디터 툴: **`Tools/KwonStudio/S3 임포터`**. AWS 설정 창은 그 안의 [설정] 버튼으로 연다.
  도구를 한 창에 모으고 싶으면 이 메뉴 대신 `S3ImporterWindow.OnGUI()` 를 직접 부르면 된다 — 그러라고 `public` 이다.
  그때는 얹는 쪽이 `position` 을 넣어주고(로그 칸이 그 값을 읽는다) `Repaint` 도 대신 해줘야 한다.
- `KwonStudio.S3`는 게임 코드에 의존하지 않는 잎 어셈블리다. 게임 코드에서 쓰려면
  그쪽 asmdef의 `references`에 `KwonStudio.S3`를 넣는다. (asmdef가 없는 코드는 `autoReferenced`로 자동 참조된다)
- 설치와 설정 채우기는 아래 「설치」·「처음 붙일 때 채워야 하는 것」 을 볼 것.

문서 ID 는 `S3Settings` 에셋에 있고 **두 개**다.

| 상수 | 용도 | 탭의 의미 |
|---|---|---|
| `SpreadsheetId` | 기획 데이터 | 탭 하나 = 테이블 하나 |
| `EnumSpreadsheetId` | 열거형 | 탭 하나 = enum 하나 |

접근 방식은 **API 키 없는 CSV export**라 두 문서 모두 "링크가 있는 모든 사용자 = 뷰어"로 공개해야 읽힌다.

> 런타임은 시트를 보지 않지만 **에디터는 굽기와 업로드 양쪽에서 시트를 읽는다.** 문서 공유를 끄면 안 된다.

## 1. 시트 작성 규칙

|  | A | B | C | D | E | F |
|--|---|---|---|---|---|---|
| **1행 (필드명)** | id | name | hp | atk speed | tags | #memo |
| **2행 (타입)** | int | string | int | float | string[] | string |
| **3행~ (데이터)** | 1 | 고블린 | 30 | 1.2 | fast\|weak | 아무거나 |
| | 2 | 오크 | 80 | 0.8 | tank | |
| | #3 | 임시 데이터 | | | | |

시작 위치는 시트마다 지정할 수 있다. 위 표는 시작이 `A1`인 경우다. (→ 2절)

### 컬럼

- **시작 행 = 필드명.** 비어 있거나 `#`으로 시작하면 그 컬럼은 코드에도 데이터에도 들어가지 않는다.
- **그 다음 행 = 타입.** 비어 있거나 `-`면 마찬가지로 무시된다. 기획용 메모 컬럼에 쓰면 된다.
- 필드명은 공백/기호를 지우고 다음 글자를 대문자로 붙인다. `atk speed` → `atkSpeed`
- 숫자로 시작하면 앞에 `_`, C# 예약어면 `@`가 붙는다.
- 서로 같은 필드명이 되는 컬럼이 있으면 임포트가 중단된다. (`atk speed`와 `atkSpeed`는 충돌)
- 한글 헤더도 되지만 필드명이 한글이 되므로 영문을 권장한다.

### 설명 행 (선택) — 생성 코드의 주석이 된다

타입 행 **바로 다음 줄**의 키 칸을 비우면(또는 `#`으로 시작하면) 그 줄은 **설명 행**이 된다.
각 칸에 적은 설명이 생성된 필드의 XML 주석으로 들어가, 코드에서 IDE 툴팁으로 보인다.

|  | A | B | C |
|--|---|---|---|
| **1행 (필드명)** | id | hp | moveSpeed |
| **2행 (타입)** | int | double | float |
| **3행 (설명)** | `#고유 키` | 최대 체력 | 초당 이동 거리 |
| **4행~ (데이터)** | 1 | 100 | 2 |

키 컬럼 칸은 **비우거나 `#`으로 시작**해야 한다 — 그래야 이 줄이 데이터가 아님이 판정된다.
`#`을 붙이면 그 뒤가 키 컬럼의 설명이 된다. 그냥 비우면 키 컬럼만 설명이 없다.

```csharp
/// <summary>
/// 최대 체력
/// <para>시트 컬럼 'hp' (double)</para>
/// </summary>
public double hp;
```

- **선택 사항이다.** 설명 행이 없는 시트는 지금까지와 똑같이 동작한다.
- 새 규칙이 아니라 **메모 줄 규칙에 얹은 것**이다 — 키 칸이 빈 줄은 원래도 데이터가 아니므로,
  설명 행을 넣어도 데이터 파싱과 행 수는 한 글자도 바뀌지 않는다.
- 설명은 **열(변수) 단위**다. 행마다 다른 메모는 아래 "행 단위 메모"를 쓴다.

### 행

- **타입 행 다음부터 데이터.**
- **키 컬럼 칸이 비어 있는 행은 데이터가 아니다.** 데이터 블록 아래나 사이에 적은 메모 줄이 여기서 걸러진다.
- 키 칸이 `#`으로 시작해도 무시된다. 키 칸에 글자를 적어야 하는 메모에 쓴다.
- 셀 안의 쉼표·줄바꿈·따옴표는 그냥 쓰면 된다. CSV 인용 처리는 임포터가 한다.

### 행 단위 메모

행마다 다른 메모를 남기려면 **무시되는 컬럼**을 하나 만든다 — 필드명을 `#`으로 시작하거나
(예: `#메모`) 타입 칸을 비우면 된다. 그 컬럼은 코드에도 에셋에도 배포본에도 들어가지 않는다.

에디터 굽기와 런타임 갱신이 같은 규칙(`S3Format`)을 보므로 어느 쪽에서도 안전하다.
Unity 에서도 보여야 하는 메모라면 그냥 `string` 컬럼으로 두면 되지만, 그건 빌드에 실린다.

### 키

- **시작 열에서 오른쪽으로 첫 번째 유효 컬럼이 자동으로 키**가 된다. (유효 = 필드명·타입이 모두 채워진 컬럼)
- `int`뿐 아니라 `string`, `enum`도 키가 될 수 있다.
- 키가 중복되면 첫 행만 살아남고 콘솔에 에러가 찍힌다.

## 2. 시작 행 / 열 — 메모가 섞인 시트

임포터 창의 시트 항목마다 **데이터 시작** 좌표를 지정한다. 시작을 `C5`로 잡으면 이렇게 읽는다.

```
      A          B        C        D        E
 1  [기획 메모 영역 — 아예 보지 않음]
 2
 3
 4
 5  메모        메모      id       name     hp      ← 필드명 (C열부터)
 6                      int      string   int     ← 타입
 7                      1        고블린    30      ← 데이터
 8                      2        오크      80
 9  ※ 밸런스 재검토 필요                            ← 키 칸(C9)이 비어서 무시
```

메모는 세 방향 모두에서 걸러진다.

| 메모 위치 | 걸러지는 방식 |
|---|---|
| 시작 행보다 위 / 시작 열보다 왼쪽 | 아예 읽지 않는다 |
| 데이터 블록 오른쪽 컬럼 | 필드명이나 타입 칸을 비워두면 무시 (또는 필드명 앞에 `#`) |
| 데이터 블록 아래·사이의 줄 | 키 컬럼 칸이 비어 있으면 무시 (또는 키 칸 앞에 `#`) |

열은 `A`, `B`, `AA` 처럼 적어도 되고 `1`, `2` 처럼 숫자로 적어도 된다.
지정한 좌표는 테이블 에셋에도 저장되므로, 런타임 갱신도 같은 위치에서 읽는다.

## 3. 타입 표

| 타입 표기 | 시트에 적는 값 | 비고 |
|---|---|---|
| `int`, `long` | `1000` | `1,000`, `12%` 도 읽어준다 |
| `float`, `double` | `1.2` | 소수점은 항상 마침표. 기기 로케일 영향 없음 |
| `bool` | `TRUE` / `FALSE` | `1/0`, `O/X`, `Y/N` 모두 인식 |
| `string` | 아무 글자 | 앞뒤 공백은 잘린다 |
| `Vector2` | `1,2` | 괄호를 씌워도 된다 |
| `Vector3` | `1,2,3` | |
| `Color` | `#FF8800` | `#RRGGBBAA`, `r,g,b[,a]` (0~1 / 0~255 모두 인식) |
| enum 이름 | `Boss` 또는 `2` | enum 이름을 그대로 적는다. 대소문자 무시. 아래 Enum 시트 참고 |
| 뒤에 `[]` | `[0.1, 0.2]` | 배열. 아래 참고 |

### 배열

대괄호로 감싸고 쉼표로 나눈다.

```
double[]    [0.1, 0.2]
string[]    [가나다라, 음음음]
int[]       7            ← 원소가 하나면 괄호 생략 가능
string[]    []           ← 빈 배열
Vector3[]   [[1,2,3], [4,5,6]]   ← 원소에 쉼표가 있는 타입은 한 번 더 감싼다
```

원소 안에 쉼표가 들어가는 문자열은 배열로 표현할 수 없다. (구분자와 구별할 방법이 없다)

**빈 칸**은 숫자 `0`, bool `false`, string `""`, 배열 길이 0으로 채워진다.
0에 의미가 있는 컬럼이라면 시트에 `0`을 직접 적어두는 편이 안전하다.

### Enum 문서

enum은 **데이터와 별도 문서**에서 관리한다. 문서를 나눠 두면 데이터 문서의 탭 목록이 곧 테이블 목록이 되고,
"문서 탭 불러오기"에 enum 탭이 섞여 들어오지 않는다.

- 문서 ID: `Remote/S3Config.cs`의 `EnumSpreadsheetId` 상수
- **탭 하나 = enum 하나**
- 등록 방식은 데이터 시트와 같다 — 창의 **Enum** 목록에 gid로 등록한다.
  **enum 탭 불러오기** 버튼을 누르면 문서의 미등록 탭이 한 번에 추가된다
- gid가 고유키라 탭 이름을 바꾸면 enum 이름도 따라간다 (설정의 **탭 이름 따라가기**)

`MonsterGrade`와 `DamageMask`가 필요하면 탭 2개를 만들고 Enum 목록에 2개를 등록한다.

**MonsterGrade 탭**

| name | value | comment |
|---|---|---|
| string | int | string |
| Normal | | 일반 |
| Elite | | 정예 |
| Boss | 10 | 보스 |
| Named | | 이어서 11 |

**DamageMask 탭**

| name | flags | comment |
|---|---|---|
| string | bool | string |
| None | TRUE | 값을 비우면 1 |
| Fire | TRUE | → 2 |
| Ice | TRUE | → 4 |

- `name` 필수
- `value` 비우면 자동 — 보통 직전 값 + 1, `flags`면 아직 안 쓴 2의 거듭제곱
- `flags` 한 줄이라도 TRUE면 `[System.Flags]`가 붙는다. `None = 0`이 필요하면 값을 직접 적는다
- `comment` 생성 코드에 XML 주석으로 들어간다
- 이름은 PascalCase로 다듬는다. `몬스터 등급` → `몬스터등급`, `low hp` → `LowHp`
- 서식·시작 좌표·메모 무시 규칙은 데이터 시트와 동일하다. 시작 좌표는 탭마다 지정한다

생성 위치는 `Generated/Enums/{이름}.cs`이고 데이터 클래스와 같은 네임스페이스라,
데이터 시트의 타입 칸에 이름만 적으면 바로 쓰인다. 목록에서 뺀 enum의 파일은 정리 대상이 된다.

## 4. 에디터에서 굽기

1. `Tools/KwonStudio/S3 임포터` 를 연다.
2. 시트를 추가한다. (gid `0`, 테이블 이름 `Monster`, 데이터 시작 `1행 A열`)
3. **전체 임포트**를 누른다.

### gid가 고유키

시트를 구분하는 건 **gid**다. 테이블 이름은 언제든 바꿔도 되고, 바꾼 뒤 임포트하면
예전 이름으로 만들어졌던 스크립트와 에셋을 **자동으로 지운다.**
gid가 같은 시트를 둘 이상 등록하면 임포트를 시작하지 않고 알려준다.

**시트 탭 이름이 바뀌면 테이블 이름이 따라간다.** gid는 그대로인데 탭 이름만 바꾼 경우,
임포트할 때 테이블 이름을 탭 쪽으로 맞추고 예전 산출물을 지운다. 시트가 원본이기 때문이다.
(반대 방향은 문서 쓰기 권한이 필요해 불가능하다.)

> 게임 코드에서 그 테이블 타입을 참조 중이라면 이름이 바뀔 때 함께 고쳐야 한다.
> 자동으로 따라가는 게 곤란하면 설정의 **탭 이름 따라가기**를 끈다.

시트 항목을 통째로 지운 경우처럼 주인이 없어진 파일은 창에 "쓰이지 않는 파일"로 표시되고,
**정리** 버튼이나 다음 **전체 임포트** 때 삭제된다.

### 동기화 확인

**동기화 확인** 버튼은 시트를 전부 내려받아 지금 프로젝트와 맞춰만 본다. 아무것도 고치지 않는다.

| 상태 | 뜻 |
|---|---|
| 동기화됨 | 스크립트도 에셋도 시트와 같음 |
| 생성 안 됨 | 스크립트나 에셋이 아직 없음 |
| 스크립트 갱신 필요 | 컬럼 추가/삭제/타입 변경 — 무엇이 바뀌었는지 함께 표시 |
| 데이터 갱신 필요 | 컬럼은 같지만 값이 다름 — 행 수 차이와 다른 행 번호를 표시 |
| 오류 | 시트를 읽지 못함 (공유 설정, gid, 시작 행/열, 서식 문제) |

등록된 시트뿐 아니라 **문서에 있는 탭 전체와도 대조한다.**

- 문서에 있는데 설정에 없는 탭 → `등록되지 않은 탭`
- 설정에 있는데 문서에 없는 gid → `문서에서 사라진 탭`

**문서 탭 불러오기** 버튼을 누르면 미등록 탭이 시트 항목으로 자동 추가된다.
탭 목록은 `htmlview` 페이지에 모든 탭의 이름과 gid가 들어 있는 걸 이용하므로 API 키가 필요 없다.
(단, 구글이 그 페이지 구조를 바꾸면 목록을 못 읽는다. 그때는 확인 결과에 사유가 표시되고
등록된 시트 확인은 그대로 동작한다.)

`Monster` 하나에서 이렇게 만들어진다.

```
Assets/02.Script/Data/MonsterData.cs        // [Serializable] 행 클래스
Assets/02.Script/Data/MonsterDataTable.cs   // ScriptableObject 테이블
Assets/08.Scriptable/S3/MonsterDataTable.asset           // 데이터가 채워진 에셋
```

시트에 컬럼이 새로 생기면 스크립트가 먼저 갱신되어야 하므로 컴파일이 한 번 돈다.
임포터가 CSV를 `Library/S3Cache`에 캐시해두고 `[DidReloadScripts]`로 컴파일 완료를 기다렸다가
에셋 빌드를 자동으로 이어서 하므로, 버튼은 한 번만 누르면 된다.

### S3Database 등록은 자동이다

임포트가 끝나면 **산출 폴더의 테이블 전부를 `S3Database`의 목록에 맞춘다** (`Editor/S3DatabaseSync.cs`).
사람이 드래그로 관리하지 않는다 — 등록이 빠진 테이블은 런타임 갱신이 아예 일어나지 않고
`Get<T>()`가 null을 주는데, 임포트는 성공한 것처럼 보여서 **실기기에서 데이터가 안 바뀌어야 비로소 드러나기** 때문이다.

- 시트를 목록에서 빼면 산출물이 정리되고, 그러면 등록에서도 자연히 빠진다.
- 깨진 참조(에셋이 사라진 항목)도 함께 치운다.
- **동기화 확인**은 고치지 않고 빠진 목록만 알려준다.

## 6. 런타임(빌드본)에서 최신 데이터 받기

런타임은 **시트가 아니라 CloudFront**에서 받는다. 테이블 전부가 번들 파일 하나에 들어 있어 **요청은 1회**다.

```
{S3Config.BaseUrl}/{S3Config.RemotePrefix}/{S3Config.BundleFileName}
→ https://d1jgof0mrb15s.cloudfront.net/config/v2/tables.json
```

```json
{ "version": "2",
  "tables": [ { "name": "MonsterDataTable", "headerRow": 1, "startColumn": "A",
                "csv": "keyIndex,hp,...\nint,double,..." }, ... ] }
```

읽기 시작 좌표(`headerRow`/`startColumn`)를 번들이 함께 나른다. 원본은 임포터 설정이고, **설정 → 번들 → 런타임 파싱**으로 곧장 흐른다.

테이블마다 따로 받지 않는 이유는 속도보다 **결과가 원자적**이기 때문이다. 폴백이 없어서 일부만 받아진 상태는
어차피 게임을 진행시키지 못하는데, 요청이 17개면 실패 기회도 17개가 된다. 번들이면 "다 받았다 / 못 받았다" 둘 중 하나다.
덤으로 CloudFront가 1,000바이트 미만은 압축하지 않으므로, 합쳐야 전부 압축된다.

번들에는 **원본 CSV 텍스트만** 담긴다. 읽기 시작 좌표(`layout`)는 지금처럼 각 테이블 에셋에 있는 값을 쓴다.

| 빌드 | 보는 곳 |
|---|---|
| 에디터 | 테섭 |
| Android 개발 빌드 (`TEST_SERVER` 정의됨) | 테섭 |
| 그 외 | 라이브 |

`TEST_SERVER`는 개발 로그(`DevelopmentLogger`)를 살리는 심볼과 같은 것을 쓴다.
**라이브 출시 시 Android 정의에서 `TEST_SERVER`를 빼면 로그 스트립과 라이브 주소 전환이 같이 일어난다.**

`RemotePrefix` 끝의 `v1`은 CSV 서식 규약이 구 빌드와 호환되지 않게 바뀔 때를 위한 탈출구다.
이미 배포된 빌드는 자기가 아는 경로만 보므로, 서식을 갈아엎을 때 `v2`로 올리고 `v1`을 남겨두면 된다.

```csharp
var report = await _database.RefreshAsync(token);   // 등록된 테이블을 한꺼번에 갱신
if (!report.IsSuccess) { /* 게임을 진행시키지 않는다 */ }
```

### 폴백이 없다

**받아오지 못하면 게임이 시작되지 않는다.** 기기 디스크 캐시도, 빌드에 구워진 데이터도 쓰지 않는다.

| 상황 | 결과 |
|---|---|
| 전부 받음 | 진행 |
| 하나라도 실패 | 로딩 중단 → 에러 화면 + `[재시도]` |

데이터 출처를 배포본 하나로 고정해서, **파이프라인이 죽었는데 옛 데이터로 조용히 도는 상태**를 없애기 위한 선택이다.
대가는 분명하다 — **오프라인에서는 실행되지 않고, CloudFront 장애는 곧 전면 중단이다.**

**테이블은 ScriptableObject 가 아니다.** 에셋이 하나도 없고, 인스턴스는 시트에서 생성된 `S3TableRegistry`가
게임 시작 때 만든다. 그래서 빌드에 구워질 데이터가 애초에 없고, 플레이 모드가 에셋을 더럽히는 일도 없다.
값을 눈으로 보려면 임포터 창의 **테이블 내용 보기**를 쓴다.

실패는 `S3LoadReport`에 모여서 온다 (`Total`·`Failed`·`FirstError`). 에러 화면 문구가 여기서 나온다.

컬럼은 **이름으로** 찾는다. 시트에서 컬럼 순서를 바꾸거나 중간에 새 컬럼을 끼워 넣어도
이미 배포된 빌드는 계속 정상 동작한다. 단, **읽고 있던 컬럼을 지우거나 이름을 바꾸면**
그 빌드는 해당 테이블 갱신에 실패하고, 폴백이 없으므로 **그 빌드는 더 이상 실행되지 않는다.**
같은 이유로 **버킷에서 키를 지우는 것도 그 키를 읽는 빌드를 죽인다** (§7 삭제 절 참고).

> **주의** — 에디터 플레이 모드에서 `RefreshAsync`를 부르면 에셋 내용이 실제로 바뀐다.
> 원격과 구워둔 값이 다르면 에셋이 더티 상태가 되니 그대로 저장하지 않도록 주의할 것.

인증이 필요해지면 `IS3RequestDecorator`를 구현해 `S3Remote.RequestDecorator`에 꽂는다.
꽂는 시점은 첫 갱신 이전이어야 한다. 지금 배포는 공개 읽기라 인증용 구현체는 없다.

### 에디터 오프라인 모드

프로젝트가 제공하는 **오프라인 모드** 스위치(`IS3RequestDecorator` 구현체)를 켜면 서버를 부르지 않고 게임이 돈다. 개발 루프에서 매번 네트워크를 기다리지 않으려는 것이다.

| 단계 | 오프라인일 때 |
|---|---|
| 기획 데이터 | `Library/S3Offline/tables.json` 을 `file://` 로 읽는다 |
| 서버 연결(UGS) | 부르지 않고 통과 |
| 세이브/재화 | `Library/CloudSaveOffline/{key}.json` 에 읽고 쓴다 |

- 로컬 번들은 **전체 임포트가 끝날 때마다 자동으로** 다시 만들어진다. 손으로 만들려면 S3 탭 **점검** 줄의 `오프라인 번들 다시 만들기`.
- 재료는 임포트 캐시(`Library/S3Cache`)라 **마지막 임포트 시점**의 내용이다. 시트를 고쳤으면 임포트를 한 번 돌려야 반영된다.
- 재화는 실제 파일에 쓰이므로 플레이를 껐다 켜도 남는다 — 서버 없이 증감·저장 경로를 확인할 수 있다.
- 켜져 있는 동안 로딩 로그 앞에 `[오프라인]` 이 붙는다. **켠 걸 잊고 "시트 수정이 왜 반영이 안 되지" 로 헤매는 게 이 기능의 유일한 함정이다.**

> 스크립팅 심볼이 아니라 EditorPrefs 토글이라 켤 때 재컴파일이 없다.
> 쓰는 쪽이 전부 `#if UNITY_EDITOR` 라 **빌드에는 이 경로가 아예 컴파일되지 않는다.**

## 7. AWS로 올리기

임포터 창 아래쪽 **배포** 줄에서 한다.

| 버튼 | 하는 일 |
|---|---|
| `AWS로 업로드` | 활성화된 시트를 **다시 받아** 번들로 묶어 올린다 (PUT 1회) |
| `AWS 상태 보기` | 올라가 있는 번들과 지금 시트 내용을 대조한다 (ETag ↔ 새로 만든 번들의 MD5) |
| `고아 키 N개 삭제` | 번들이 아닌 키가 남아 있을 때만 나타난다 (아래 삭제 절) |
| `설정` | 키·리전·버킷 입력 (별도 창으로 뜬다) |

- 올라가는 건 `config/v1/tables.json` **하나뿐**이다.
- 대상은 **테섭이 기본**이고, 라이브를 고르면 확인 다이얼로그가 한 번 뜬다.
- `Cache-Control: max-age=60`으로 올라간다. 그래서 **무효화를 따로 걸지 않아도 1분 안에 반영**된다.
- **시트를 한 장이라도 못 받으면 업로드 자체를 중단한다.** 반쪽 번들을 올리면 빠진 테이블을 읽는 빌드가 실행되지 않는다.
- 번들 내용은 **같으면 바이트도 같게** 만든다(시각 같은 값을 넣지 않고 항목 순서를 고정). 그래야 상태 보기의 ETag 대조가 성립한다.
- **업로드는 예전 키를 자동으로 지우지 않는다.** 지우는 건 아래 삭제 절에서 손으로 한다.
- 굽기 캐시(`Library/S3Cache`)를 재활용하지 않고 시트에서 다시 받는다. 그 캐시의 파일명은 탭 이름(`Monster.csv`)이라
  원격 키(`MonsterDataTable.csv`)와 다르고, 마지막 임포트에 포함된 탭만 들어 있어 조용히 빠지기 때문이다.

### 자격 증명

`AwsCredentials`가 전부 `EditorPrefs`(이 PC에만)에 저장한다. **리포에는 파일이 생기지 않으므로 커밋 사고가 없다.**
대신 평문으로 남으므로 여기 넣는 키는 업로드 전용 IAM 사용자여야 한다. 필요한 권한은 둘뿐이다.

```json
{
  "Version": "2012-10-17",
  "Statement": [
    { "Effect": "Allow", "Action": ["s3:PutObject", "s3:DeleteObject"],
      "Resource": "arn:aws:s3:::<bucket>/config/*" },
    { "Effect": "Allow", "Action": "s3:ListBucket", "Resource": "arn:aws:s3:::<bucket>",
      "Condition": { "StringLike": { "s3:prefix": "config/*" } } }
  ]
}
```

`s3:ListBucket`의 Resource는 **객체가 아니라 버킷**이어야 한다. 여기가 틀리면 연결 테스트가 `AccessDenied`로 떨어진다.
`s3:DeleteObject`는 고아 키 정리에 필요하고, `config/*` 밖으로는 나가지 않는다.

### 테이블을 없앨 때 — 순서를 지켜야 한다

번들 구조에서 **테이블을 시트에서 지우면 그 즉시 번들에서 빠진다.** 그런데 `S3Database`의 테이블 목록은
빌드에 구워져 있어서, 이미 배포된 빌드는 그 테이블을 계속 찾는다. 못 찾으면 `번들에 이 테이블이 없습니다`로
실패하고 — 폴백이 없으니 — **그 빌드는 실행되지 않는다.**

그래서 순서가 이렇다.

1. `S3Database` 목록과 게임 코드에서 그 테이블을 떼고 **새 빌드를 배포한다.**
2. 옛 빌드가 충분히 빠질 때까지 **시트 탭은 그대로 둔다.** (번들에 계속 실려 나간다)
3. 그 다음에 시트에서 지우고 업로드한다.

거꾸로 하면(시트 먼저 삭제) 그 시점의 **모든 배포본이 멈춘다.** 컬럼을 지우거나 이름을 바꾸는 것도 같은 등급의 변경이다.

> 예전에는 "버킷의 옛 키를 1~2 릴리즈 뒤에 지운다"가 유예 규칙이었다.
> 번들이 되면서 유예 대상이 **버킷 키에서 번들 내용으로** 옮겨갔다.

### 버킷에 남은 키 정리하기

번들 말고 프리픽스 아래 남아 있는 키는 전부 **고아**다 — 옛 형식의 테이블별 CSV이거나, 이름이 바뀐 흔적이다.
시트에서 탭을 지워도 번들에서 빠질 뿐 버킷에는 흔적이 남지 않으므로, 실질적으로는 형식 전환 뒤 정리에 쓰인다.

`AWS 상태 보기`가 `? 시트에 없는 키`로 표시하고 그때만 `[고아 키 N개 삭제]` 버튼이 나타난다.
지울 키 목록을 보여주는 확인 다이얼로그를 거치며, 라이브면 한 번 더 묻는다.

> **폴백이 없어진 뒤로 삭제가 위험해졌다.** 전에는 옛 키를 지워도 그 키를 읽던 배포본이 구워진 데이터로 물러났다.
> 지금은 **그 빌드가 아예 실행되지 않는다.** 그래서 업로드가 자동으로 지우지 않고, 손으로 고르게 되어 있다.
> 실제 삭제는 **그 키를 읽는 배포본이 없다고 확신할 때** — 보통 1~2 릴리즈 뒤에 한다.

### 연결이 안 될 때

`AWS 설정` 창의 `연결 테스트`가 S3가 돌려준 오류 코드를 그대로 보여준다.

| 코드 | 원인 |
|---|---|
| `SignatureDoesNotMatch` | 서명 계산 문제. 시스템 시계가 5분 이상 어긋나도 난다 |
| `AccessDenied` | IAM 정책. `s3:ListBucket`의 리소스는 객체가 아니라 **버킷**이어야 한다 |
| `PermanentRedirect` | 리전이 버킷과 다르다 |
| 인증서 오류 | 버킷 이름에 점(`.`)이 있으면 https 인증서가 맞지 않는다 |

### 릴리즈 전 체크리스트

**순서가 중요하다.** 아래 1~2를 건너뛰고 3부터 하면, 에디터를 뺀 모든 빌드가 빈 라이브 버킷을 보게 된다.

1. **라이브에 올린다** — 임포터 창에서 대상을 `Live`로 바꾸고 `[AWS로 업로드]`. 확인 다이얼로그가 한 번 뜬다.
2. **`[AWS 상태 보기]`로 번들이 `✓ 일치`인지 본다.** `✗ 버킷에 없음`이나 `⚠ 시트와 다름`이면 릴리즈하지 않는다.
3. **그 다음에** `ProjectSettings` → Android 정의에서 `TEST_SERVER`를 뺀다.
4. **빌드 후 실기기에서 확인한다.**
   ```bash
   adb logcat -s Unity | grep "\[S3\]"
   ```
   `테이블 갱신 완료. 다운로드 17 / 캐시 0 / 실패 0` 이 보여야 한다.
   이 시점엔 `DevelopmentLogger`가 죽어 있지만 `S3Database`·`S3Remote`의 로그는 남으므로 이 줄은 보인다.

> **1~2를 빠뜨리면 게임이 아예 실행되지 않는다.** 폴백이 없어서 라이브 버킷이 비어 있으면 모든 유저가 에러 화면에서 멈춘다.
> 예전처럼 "구워진 데이터로 조용히 도는" 완충이 없으므로, 업로드 누락은 곧 서비스 중단이다.

> **심볼 방향 주의** — `TEST_SERVER`는 **있으면 테섭**이다. 흔한 `*_LIVE` 류와 반대 방향이니 헷갈리지 말 것.
> 이 심볼 하나가 개발 로그 스트립과 서버 주소를 동시에 가른다.

## 설치

### 개발 중 — 로컬 클론을 `file:` 로 (권장)

패키지를 고쳐 가며 쓰는 동안은 이쪽이다. git URL 로 참조하면 `Library/PackageCache` 에
**읽기 전용**으로 들어가서, 한 줄 고칠 때마다 커밋 → 푸시 → re-resolve 를 돌아야 한다.
폴더를 `file:` 로 가리키면 PackageCache 로 복사되지 않아 **수정 즉시 반영**되고,
그 폴더가 그대로 git 리포라 커밋·푸시도 된다.

```json
"com.kwonstudio.s3": "file:../../../Packages/Kwon.S3"
```

> `file:` 경로는 **프로젝트의 `Packages` 폴더 기준 상대경로**다.

### 안정된 뒤 — git URL

```json
"com.kwonstudio.s3": "https://github.com/human6014/Kwon.S3.git#v0.1.1"
```

패키지가 리포 루트에 있으므로 `?path=` 가 필요 없다. 태그를 붙이지 않으면 기본 브랜치를
한 번 resolve 해서 `packages-lock.json` 에 커밋 해시를 박는다 — 갱신하려면 lock 의 해당
항목을 지우거나 태그를 올린다.

### 함께 필요한 것

**UniTask 는 이 패키지가 선언할 수 없다.** git 패키지라 `package.json` 의 `dependencies` 로
해결되지 않는다(UPM 은 레지스트리 패키지만 자동 설치한다). 프로젝트 manifest 에 직접 넣을 것:

```json
"com.cysharp.unitask": "https://github.com/Cysharp/UniTask.git?path=src/UniTask/Assets/Plugins/UniTask"
```

## 처음 붙일 때 채워야 하는 것

| 에셋 | 기본 자리 | 무엇 |
|---|---|---|
| `S3Settings` | `Assets/Resources/S3/S3Settings.asset` | **런타임이 읽는다.** 테섭/라이브 CloudFront 주소, 배포 경로 prefix, 스프레드시트 ID 3개 |
| `S3ImportSettings` | `Assets/Settings/S3/S3ImportSettings.asset` | 에디터 전용. 시트 탭(gid) 목록, 생성 경로·네임스페이스 |

- **둘 다 없으면 임포터 창에서 만들 수 있다.** `S3Settings` 는 `배포 설정` 줄의 [만들기] 버튼.
- 찾는 방식이 경로가 아니라 **타입 검색**이라 만든 뒤 `Assets/` 안에서 옮겨도 계속 찾아낸다.
  단 `S3Settings` 만은 런타임에 `Resources.Load` 로 읽으므로 **`Resources` 아래를 벗어나면 안 된다.**
- AWS 자격증명(액세스 키·리전·버킷)은 에셋이 아니라 **`EditorPrefs`** 에 있어 리포에 남지 않는다.
  해당 버킷 put/list 권한만 가진 전용 IAM 사용자를 쓸 것.

생성 코드의 기본 자리는 `Assets/02.Script/Data`, 네임스페이스는 `Game.Data` 다.

## 로그

이 패키지는 `Debug.*` 를 그대로 쓴다. 프로젝트의 `DevelopmentLogger` 같은 래퍼는
`Assembly-CSharp` 에 있어 asmdef 를 가진 패키지가 참조할 수 없다. 의도된 제약이다.

## 검증

`verify~/` 에 빈 프로젝트로 컴파일·동작을 확인하는 절차가 있다. `~` 로 끝나는 폴더라
Unity 는 이 폴더를 읽지 않는다.
